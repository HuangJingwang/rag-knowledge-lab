# RAG Knowledge Lab

最近在做会议模块的 Agent 开发，于是调研了大量方案。老板让我开一个内部技术分享会，但我觉得只讲某一个框架会太片面，于是整理了从传统 RAG 到 OKF 0.2 的整体技术脉络，作为这次分享的内容。

这是整理这些资料时做的一个小项目，包含一篇技术文章和一个配套示例网站。希望读者看完后，能大致理解这些方案为什么出现、各自解决什么问题，再通过几个具体例子加深理解。

## 里面有什么

**文章是主要内容。** 从传统 RAG 开始，介绍 GraphRAG、LightRAG、时序知识图谱、PageIndex、Agentic RAG、LLM Wiki 和 OKF 0.2。每部分会讲它的来由、基本原理、适用场景和不足，配有流程图和对比说明，不深入到源码细节。

这些方案也不全是同一类东西：有的负责检索，有的组织查询过程，有的维护知识，OKF 则是一种知识格式规范。文章会说明它们之间的联系，方便理解和比较。

**网站用来对照着看例子。** 里面放了一组虚构的文档、任务和会议记录。可以阅读原文、查看文本怎么切块、输入问题看检索结果，也可以打开图谱，看看人物、任务和项目是怎么关联起来的。想继续了解数据结构的话，还可以进入 Milvus 和 Neo4j 的管理界面。

## 可以学到什么

- 了解一次 RAG 查询的大致过程：资料怎么准备，相关片段怎么找，为什么找到了相似内容仍可能答不完整。
- 理解图关系、文档目录、时间信息分别能补充什么，以及 GraphRAG、LightRAG、PageIndex 等方案的区别。
- 了解资料持续变化时，怎样追溯来源、判断结论是否仍然有效，以及 LLM Wiki 和 OKF 在知识整理中承担的作用。

比如，“支付回调失败后能不能重试”，需要同时读到规则和适用条件；“负责人调走后会影响哪个项目”，需要把几份资料中的关系连起来。示例围绕这类小问题展开，可以一边读文章，一边查看对应的数据和结果。

## 怎么看

如果只想读文章，下载 [article/article.html](article/article.html) 后用浏览器打开即可，图片已经包含在文件中，无需启动数据库。

想操作示例网站，需要先安装 Docker 和 Docker Compose v2，然后运行：

```bash
git clone https://github.com/HuangJingwang/rag-knowledge-lab.git
cd rag-knowledge-lab
./start.sh
```

启动后打开：

- [文章](http://localhost:8018/article/)：阅读各方案的介绍。
- [示例网站](http://localhost:8018/)：查看原文、切块和检索结果。
- [分步案例](http://localhost:8018/examples)：查看不同方案对应的例子。

首次启动需要联网下载依赖和容器镜像，无需填写模型 API Key。建议为 Docker 分配至少 8 GB 内存、预留 10 GB 磁盘空间。端口设置、数据库入口和停止方法见[部署说明](docs/deployment.md)。

## 示例做到什么程度

这是辅助理解原理的学习项目。向量由本地模型实际计算，数据库检索也会真实执行；图关系和部分案例步骤是提前整理好的，目前没有接入 LLM 自动抽取和答案生成，也没有完整复现所有框架。

页面会标明哪些步骤是实际查询、哪些是教学示例。更具体的说明放在[实现范围与数据结构](docs/implementation.md)，已有的检查结果见[验证记录](VERIFIED.md)。

文章中保留了参考资料和官方项目链接，方便继续阅读。模型与依赖的来源见[第三方说明](THIRD_PARTY_NOTICES.md)。
